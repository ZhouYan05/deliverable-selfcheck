# 规则册 · deliverable-selfcheck

> 这本册子回答一个问题：**为什么工具只查这些、不查那些？**
> 规则不是凭空设计的，每一条都对应一次真实失败（或一次真实的「差点误报」）。
> 代码里的规则定义在 [`../src/deliverable_selfcheck/rules.py`](../src/deliverable_selfcheck/rules.py)，
> 本文是它的**动机与证据**，两者必须同步修改。

---

## 0. 规则的组织方式：按「平台真正会检查什么」分作用域

同一个模式，在仓库正文里是正常文本，在提交字段里却是拒单理由。所以规则不是一把梭，而是**分层**：

| 作用域 | 常量 | 启用规则 | 为什么这样切 |
| --- | --- | --- | --- |
| 仓库文件内容（默认） | `CONTENT_RULES` | 只有真凭据（`SECRET_RULES`） | 平台的敏感信息过滤作用在**提交字段**上，不扫仓库正文。无差别扫正文会把 YAML 的 `runs-on` 值、文档里的说明性冒号全部误报成阻塞，工具立刻失去可信度 |
| 仓库文件内容（`--strict`） | `STRICT_CONTENT_RULES` | 真凭据 + 「冒号 + 空格」 | 给「想把整段文本当提交字段来审」的场景留的口子。默认关闭，因为误报多 |
| 提交字段（`--title` / `--summary`） | `METADATA_RULES` | 真凭据 + 「冒号 + 空格」 | 误判就发生在这里，这是最贴近平台真实行为的一层 |

一个刻意的设计：`CONTENT_RULES` 是 `SECRET_RULES` 的**别名**而不是副本，
这样「默认内容规则 = 真凭据」这条不变量在类型层面就只有一个来源，不会改一边忘一边。

## 1. 规则族 1 · 交付物文件名匹配（不是「通配符」）

### R1 · 字面子串匹配（`normalize_requirement` / `match_requirement`）

- **作用**：把 `requiredDeliverables` 里的一个 token（如 `*AI日志*`）还原成它真正的匹配方式。
- **算法**：`token.strip().strip("*").strip()` → 得到字面 needle → 判断 `needle in filename`（默认 `casefold` 大小写不敏感）。
- **致命细节**：`*` 不是通配符语法，**会被剥离**；剩下的字符串按**连续字面片段**匹配。
- **证据（实测，C3 提交）**：

  | token | 文件名 | 判定 | 原因 |
  | --- | --- | --- | --- |
  | `*AI日志*` | `AI日志.md` | ✅ | 字面包含 `AI日志` |
  | `*AI日志*` | `AI_工作日志与AAR.md` | ❌ | 下划线把 `AI` 和 `日志` 物理隔断，字面序列 `AI日志` 不出现 |
  | `*AI日志*` | `AI_LOG.md` | ❌ | 英文名不含这四个中文字 |
  | `*AAR*` | `AI_工作日志与AAR.md` | ✅ | 字面包含 `AAR` |

- **代价**：交付物其实齐全，却因一个下划线被平台判 `missing_artifacts`，artifactCompleteness 直接封顶 5/15。
- **可操作结论**：一个文件要同时满足两类交付物时，文件名必须**同时字面包含**两个关键词（如 `AI日志与AAR.md`）。

### R2 · 近似命名告警（`near_miss`）

- **作用**：在「没命中」之外，额外区分出「**看起来想满足、但被多余字符拆开**」的情况。
- **算法**：needle 的字符是否按顺序、允许被插入额外字符地出现在文件名里（子序列匹配）。
- **严重度**：`warn`，默认**不影响退出码**；只有 `--strict` 才升级为阻塞。
- **为什么值得单独列一层**：这类问题修起来只要改个文件名，是「性价比最高的一条提示」，但它不是错误——真实仓库里 `demo_2024.py` 之类的命名会被子序列误伤，所以不能默认阻塞。

## 2. 规则族 2 · 敏感信息形态（`SECRET_RULES`）

平台对提交字段做敏感信息过滤。以下模式**无论扫哪里都必须拦**，因为它们的的确确是凭据形态：

| rule_id | 模式（正则） | 严重度 | 依据 |
| --- | --- | --- | --- |
| `openai_key` | 以 `sk-` 开头、后接 16 个以上 `[A-Za-z0-9_-]` | block | 平台报错文案里点名了 `sk-` 形态 |
| `github_token` | `ghp_` / `gho_` / `ghs_` / `github_pat_` 前缀 + 20 位以上 | block | GitHub 个人访问令牌的标准前缀 |
| `aws_key` | `AKIA` + 16 位大写字母数字 | block | AWS Access Key ID 固定形态 |
| `private_key_block` | `-----BEGIN ... PRIVATE KEY-----` | block | PEM 私钥块 |
| `generic_secret_assign` | `api_key` / `access_token` / `secret` / `password` 等词后跟 `:` 或 `=` 再跟 8 位以上值 | block | 明文凭据赋值 |

设计取舍：这一族**故意保持窄**。宁可漏掉自造格式的密钥，也不要把正常文本卷进来——一个天天误报的检查器，用户第三次就不看了。

## 3. 规则族 3 · `word: word` 陷阱（`COLON_SPACE_RULES`）

| rule_id | 模式 | 严重度 |
| --- | --- | --- |
| `keyvalue_colon_space` | `\S:\s+\S`（非空白 + 英文冒号 + 至少一个空格 + 非空白） | block |

- **现象**：平台把「英文冒号 + 空格」读成 key/value 形态，判定为疑似密钥/Token，**整单拒绝**且**不指出位置**。
- **无差别打击**：键不限于英文——中文项目名同样中招。
  真实被拒的标题：`C4 技能分享与传播: deliverable-selfcheck 交付物自检器`
  → 报告：`字段「projectTitle」提交内容疑似包含敏感信息（密钥/Token（sk- 或 api key 形态））。请脱敏后重新提交。`
- **修法**：把英文冒号换成破折号 `-` 或全角冒号 `：`，其余文字不动即可通过。
- **为什么默认不扫仓库正文**：正文里的 `runs-on: ubuntu-latest`、`Note: 说明`、Markdown 列表说明都是正常写法。
  **反例被测试钉死**：`tests/test_checker.py` 里既有一条「中文标题带冒号必须 BLOCK」，也有一条「正文里的说明性冒号不许误报」。
- **误报边界（已知）**：URL 的 `https://`、时间 `12:30`、`注意: 见下` 在 `--strict` 下会命中。这是 `--strict` 默认关闭的直接原因。

## 4. 门槛与退出码的关系

| 报告字段 | 内容 | 影响 `Report.ready` |
| --- | --- | --- |
| `missing` | 一个都没命中的必需关键字 | ✅ 有则 `False` |
| `near_misses` | 近似命名（warn） | ❌ 默认不影响；`--strict` 下影响 |
| `content_issues` | 正文命中，severity = `block` | ✅ 有 block 则 `False` |
| `metadata_issues` | 提交字段命中，severity = `block` | ✅ 有 block 则 `False` |

退出码：`0` = READY、`1` = BLOCKED、`2` = 参数错误。`--strict` 只改变「哪些命中算 block」，不改变枚举。

## 5. 怎么加一条新规则（流程，别跳步）

1. **先有证据**：一条真实被拒/被漏判的记录（原始报错文案 + 复现命令）。没有证据不进规则册。
2. **定作用域**：它属于「真凭据」还是「形态类」？该不该进仓库正文扫描？——先答错这一步，误报就来了。
3. **写测试**：**同时**加正向用例（必须拦）和反向用例（不许误报）。反例比正例更重要。
4. **改 `rules.py`**：`TextRule(rule_id, pattern, severity, hint)`，`hint` 必须写出「怎么改」而不只是「哪里错」。
5. **更新本册**：把上面那张表补一行，注明依据与反例。
6. **跑回归**：`python -m unittest discover -s tests -v` 必须全绿。

## 6. 已知限制（不假装覆盖）

- 不覆盖平台过滤规则的**全量**，只覆盖实测撞到并复现过的形态。
- 只扫**后缀白名单**内的文本文件，单文件上限 256KB，二进制不扫。
- 不做模糊匹配、不做语义判断、不联网、不调用模型：**同样输入永远同样输出**。
- 这是平台校验的**近似实现**，最终以平台返回为准。见 [`../docs/USAGE.md`](../docs/USAGE.md) 第 7 节边界表。
